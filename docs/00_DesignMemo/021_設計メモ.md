# 021.スプレッドシートライクなデータベース簡易エディタ設計メモ

## 概要

汎用的なWebアプリとして、自分専用に構築する。データベースを操作しつつ、無駄ではないが余計な機能は省いた、そのようなある種pgAdminのようなWebアプリである。特にどんな自前のWebアプリでも、共通アプリとしてAPI化しておけば、URLを少し変えるだけで人の行う作業として楽にデータベースアクセスができる。また、これを応用してxlsxやCSVをアップロードすれば、データベースのテーブルにインポートしたり、手動でマッピングしながらインポートもできる+クエリとして実行することでSQLファイルの作成もシームレスに可能となる、そのようなアプリである。

## アプリ構成

- フロントエンド:React
- バックエンド:Java Spring Boot
- アプリ用DB:PostgreSQL
- アーキテクチャ: クリーンアーキテクチャ
- その他:Docker docker-compose
- その他2: 個人でこのアプリ自体をカスタマイズ可能なように構築用プロンプトもGitHubに置いておく

  - SQLとしては単一のSQLとして保存するため、サイドバーないしモーダルではメモ帳と記入するエリアを区切って置く。
  - SQLとメモ帳間の移動もショートカットキーでできるようにするが、TABキーだけで移動はさせないようキー配置をする
  - 保存はSQL保存ボタンとメモ帳保存ボタンで実現し、データベースのレコードとして保存する。これによりプロンプトとしてもメモ帳やSQLが機能してくるためだ。なお、環境依存文字などが入ったメモ帳やSQLでもレコードに保存できるようにしたいが、仕様上不可能ないし困難ならば保存できないように文字を強制的に置換する処理を保存と同じように設定する。なお、ローカルにもメモ帳やSQLを保存できるよう、ローカル保存ボタンも用意しておく。
  - SQL呼び出し機能としてはレコードにタイトルをつけて保存したSQL文字列データを、タイトルで選択して呼び出す。ただしこれらもタイトル数が多くなりすぎると分からなくなるため、後述するテーブル編集機能でスプレッドシートライクに閲覧しながら整理可能な対象テーブルとしておく。
  - メモ帳の保存に関しては、各テーブルにひとつだけヒモ付くものとしてレコードを作成できる。つまり、後述するテーブル編集機能で開いているテーブルからこの画面が呼び出された=このテーブルに関することないし作業中の話なので、レコードを複数用意する必要がないのである。もし別のテーブルの話をメモりたいならば、別タブでテーブル編集画面を開いてメモ帳を呼び出せばいいのである。トレードオフとするならば、管理の正しさや柔軟さよりシンプルかつスピーディーなメモ帳のほうがよりエンジニアには喜ばれる気がする（私はその方が嬉しい）。

- 編集対象テーブル変更機能
  - ヘッダーにボタンとコンボボックスを配置する。
  - 画面にテーブルデータを反映させるないし別タブで開くための変更ボタンを押下することで、画面変更を実施する。
  - コンボボックスにはテーブル名のみを表示かつ、シンプルにするため昇順で並べるようにする。
  - テーブル名の取得タイミングは、top画面で選んだデータベース内の接続設定で定義したユーザがアクセス可能なテーブルを全取得してくことで実現する。ユースケースとしてもデータベース接続後にテーブル編集したいなら確実にまずはどれかを選ぶ行為が必要だし、切り替えしたいときは別タブや保存してから切り替えた方がブラウザ上の移動の楽さや面倒の無さが叶えられるからだ。また、他のデータベースとも見比べたいなどがあるならそれこそ別タブないし別ウインドウのほうがいい（Alt+Tabとかで見比べるほうがエンジニアとして自然）
  - なお、切り替え時=別タブとなるのは現在の画面がテーブル編集画面以外のときとして、テーブル編集画面ならまずは保存済みチェックが入り、その後モーダルで別タブで開くか？をいいえをデフォルトとして、はいを選んだときに別タブ起動するといった導線にしておく。もちろんモーダルではTABキーで、はいにフォーカスを当てられるようにする。
  - テーブル選択や変更実施自体にはショートカットキーを配置しないようにしておく。今後考えてもいいんだが、マシンスペックによっては画面遷移とリクエストのタイムラグによってデータベースに悪影響を与えることが多いからである。
  - また、ショートカットキーで変更する意味や価値が感じられないし、もし見比べるなら別タブか機能で充実させる方法で良いのでは？と思ったからである。
  - 比較機能は今後考えてもいいが、当初から入れるのは私自身重荷なので止めておく。
- 編集中テーブルの未保存チェック処理
  - タブを閉じる前や、テーブルを切り替えるとき、ブラウザ自体を閉じるときなどに発火し、モーダルで確認を取る。このモーダルもシンプルに｢未保存のテーブル編集内容がありますが、保存しなくてよろしいですか？｣とモーダル表示してはい、保存するを選択するだけのシンプルさにする。特にフォーカスははいや保存するにはデフォルトでは当てず、TABとSHIFT+TAB等によって選択できるようにする。もちろんマウスでもいいんだが、ショートカットキーでフォーカスを移動できるようにはしたい。
- 編集中テーブルの変更内容保存および反映機能
  - Ctrl+Sで保存可能だが、これはテーブルに直接保存ではなく、Selectした時点での画面上にもつデータの履歴として持つこととする。本当のテーブルへのデータ反映はヘッダーにあるボタン押下とモーダルでの確認で反映させることとする。
  - このワンクッションによって、編集中に別のプロセスによって値が変わった場合の上書きに対する手動判断が可能になるし、衝突する場合のどちらを優先するかもシステムで判断しなくて良くなる。また、衝突検知処理で衝突しない場合もあるので、ワンクッションにより衝突検知処理の実行自体もタイミングとして独立させられるし、衝突しないから保存するのようなシステマチックすぎる処理にしなくて済む。
  - 衝突時は画面が同タブで切り替わることとし、選択しながらどっちを優先するかをユーザが選べるようにする。さながらVSCodeのDiff機能のようなUIだと楽さが増えると思う。
- CSVファイルのインポートおよびカラムの手動マッピング機能
  - データ自体をローカルからアップロードし、テーブルを選んで、アップロード後の手動でのテーブルカラムと列のマッピングや、アップロード直後にカラムを検知したときの画面デフォルト値としてのマッピングなどを実装する。
  - 特にインポートしたくないローカルデータの列も含んだデータがインポートするときに邪魔になるが、カラムマッピングを手動および目視確認する前提のアプリケーションならば、前処理不要で気にせずインポートが実現できると思う。
- スプレッドシートファイルのCSV化機能
  - これは画面上で変換しなくともできる処理だが、xlsxファイルのなかに図形があったりする場合を懸念しつつ、単にスプレッドシートブックの複数シートを選んでからCSVにしておけば、インポートしたCSVデータとしてもローカルに保存することが可能になる。要はCSVの変換自体やファイルとしての別名保存がシームレスに可能となる、一石二鳥の地味に便利な機能である。
- ファイルアップロード機能
  - SQLファイルやCSV、xlsx、メモ帳として表示したいテキストファイルといったものをアップロードするもの。
  - 機能というより処理かもしれないが、画面としてはインポート機能の前にこの画面があるイメージで、アコーディオンのようにしてもいいが、導線としてはインポートしたいときに最初に選ばなければならないものとしてあえて定義しておく。特にメモ帳のアップロードは追加なのかレコード上書きなのかを選ぶといった唯一の導線が発生するので、同一画面としても他の機能とは分離した画面にしておきたい。
- テーブルデータエクスポートおよびダウンロード機能
  - エクスポートするテーブルを単一ないし複数選べるようにする。ファイル名は固定でDB名テーブル名タイムスタンプとする。
  - 繋いでいるDBのテーブルのみを対象とする。
  - 拡張子はCSVとxlsx、マークダウンの3種類にする。YAMLもいいが今後の課題兼アイディアとして残しておく。
  - ダウンロード先はブラウザのデフォルトとする。
  - 画面としてはヘッダーに配置したいと思っている。なお、編集中の場合はモーダルで確認を取らずに現在のDB情報をダウンロードするようにする。ただし、編集中データ自体もテーブル選択肢のドロップボックスの値として用意することでダウンロード可能としておく。
